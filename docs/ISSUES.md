# ISSUES -- k5p-jpeg-encoder

所有问题最终以 **17/17 仿真回归全 PASS**(见 LOG)收口。

## I-01 fdct1d_llm 常数位宽截断

- **现象**:tb_fdct1d 大量 X / 数值错。
- **根因**:`C_3_072711026=25172`、`C_2_562915447=20995`、`C_2_053119869=16819`
  超出 14 位有符号范围,写成 `14'sd25172` 后按字面量截断;15 位互连线又使
  位 15 悬空,算术被 X 污染。
- **修复**:常数改 `16'sd...`,TB 互连线 15→16 位,输出切片 [14:0]→[15:0]。
- **教训**:有符号字面量必须核对 `2^(N-1)-1`;互连位宽 = 端口位宽,差一位就是 X。

## I-02/I-03 dct2d 发号状态机(多轮)

- **现象**:系数流整行丢失 / 每块 9 组。
- **根因**(迭代修了三次):
  1. `s_eol` 曾用 `else if` 抢占偶列分支,行尾 pair 被吞(decim 侧,见 I-02 原始记录);
  2. coef_valid 的清除与 drain 再置位在同一 always 内顺序颠倒,背靠背 drain 丢行;
  3. 发号列/行计数器用跨拍陈旧值。
- **修复**:清除先于置位;issue 时刻寄存 core_slot/core_idx/core_comp;
  填充列号改为"状态机当时值"(fill_fcol)。
- **教训**:同一 always 里的"先清后置"是有意设计,注释必须写明,后人别"优化"掉。

## I-04 ModelSim `disable` 入未进入块 → SIGSEGV

- **现象**:tb_fdct1d 崩溃,`vsim_stacktrace.vstf`,信号 11。
- **根因**:`disable <label>` 的目标块从未被进入(while 重写后的残留)。
- **修复**:TB 重写为 while 循环 + task,不用跨块 disable。
- **教训**:disable 的目标必须保证已进入;TB 里优先用 `disable fork`。

## I-05 huff_enc ZRL 急于发射

- **现象**:全零块输出膨胀 4 倍(每 16 零必发 ZRL)。
- **根因**:`run>=16` 时无条件发 ZRL——但 JPEG 只在**非零系数之后**才需要 ZRL,
  行尾零串只需 EOB。
- **修复**:ZRL 仅当 `din != 0 && run >= 16`。
- **教训**:编码器"何时发码"要严格对齐码表语义,不是"到条件就发"。

## I-06 huff_enc 双 slot 握手

- **现象**:引擎滞后时丢 2 个 Y 块/MCU。
- **根因**:`q_ready = !(slot_v[0] && slot_v[1])` 允许写者覆写引擎未消费的块。
- **修复**:`q_ready = !slot_v[wslot]`(写者自己的目标 slot 必须为空)。
- **教训**:双缓冲握手以"写者的目标槽"为准,不是"有一个空就行"。

## I-07 打包器累加器污染

- **现象**:字节 2 = f4 vs 28。
- **根因**:drain 后 `acc` 只右移不清高位,下次 put 左移把旧位拖进有效域。
- **修复**:`acc_drain = acc & ((48'h1 << (nbits-8)) - 1)`,保持有效域右对齐、高位恒零。
- **教训**:移位式打包器每一步都要维持"有效位右对齐、高位零"的不变量。

## I-08 wslot 计数越界(X 指针)

- **现象**:恰好处理完 2 块后引擎饿死,`q_ready` 变 X。
- **根因**:`wslot <= wslot + 1'b1`,2 位寄存器走 0,1,**2,3**;`slot_v[2]` 越界读 X。
- **修复**:`wslot <= wslot ^ 2'd1`(翻转)。
- **教训**:**N 项数组的游标用 log2 位宽 +1 计数只对 2 的幂深度成立;2 项数组必须翻转。**

## I-09 帧尾 pad 两处错误

- **现象**:多 1 字节 / out_last 不来。
- **根因**:eob 路径用 pre-put 的 nbits_shift 少算 4 位;k==63 路径在
  nbits 恰为 8 的倍数时 `[2:0]==0` → pad_n=8,白垫整字节。
- **修复**:两路统一 `pad_n = (4'd8 - nbits_next[2:0]) & 4'd7`(即 (-n) mod 8)。
- **教训**:对齐类计算写成 mod 8 一行式,别拆特例。

## I-10 P2 幽灵拍

- **现象**:每块系数多一组 row0;P2ISS 序列 9 次。
- **根因**:`p2_irow` 3 位在 7 后回绕 0,清 `p2_active` 的 drain 与第 9 次
  continue 同拍,挡不住多发;多发组 `coef_last=0` 混入下一块。
- **修复**:(最终形态见 I-12)pass 的"还有没有发号"用**自己的**进度寄存器判定。
- **教训**:多拍 pass 的收尾必须显式判定,不能依赖"下一拍状态机变了"。

## I-11 探针挂死主线程

- **现象**:带探针仿真永不结束,3M 周期看门狗形同虚设。
- **根因**:探针 `forever` 放在 `join_none` 之后的主线程,`wait(done_flag)` 永不可达。
- **修复**:`while (!done_flag)`;后续重构为独立 always 块。
- **教训**:调试探针也要有退出条件;探针代码本身会改变仿真行为。

## I-12 共享 core_idx 判定 pass 完成 → 死锁

- **现象**:I-10 修复后 bytes=2,管线彻底停。
- **根因**:`p1_more = (core_idx != 7)`——core_idx 是 **P1/P2 共享**的在途结果
  索引,P1 发完 col7 后 core_idx=7 卡死 P2 的恢复判定。
- **修复**:`p1_more = !p1_active || (p1_icol != 0)`(自有进度寄存器,发完自动回 0);
  同理 p2_more。
- **教训**:**共享资源的游标不能当作某个使用者的状态;每个 pass 用自己的进度寄存器。**

## I-13 Y 舍入偏置

- **现象**:flat 过、noise/grad/pat 全挂;系数与 golden 差 ~35。
- **根因**:注释写 `Y=(77R+150G+29B+128)>>8`,实现却没加 128(floor 截断)。
  差值直方图 {-1:35, 0:29} 单向偏;flat 常量图对 ±1 免疫所以侥幸。
- **修复**:py 乘积内加 `+ 18'd128`。
- **教训**:**注释与实现必须互审;常量图四类全绿的验证要警惕"常量对结构 bug 免疫"。**

## I-14 1 深系数缓冲竞态

- **现象**:每块系数第 3 行整行错(值 = 另一行的输出);COEFOVR 检测 94 次。
- **根因**:发号闸采 `coef_ready` 于发号拍,drain 落在下一拍,quant 的 ready
  恰在该拍撤销(它刚收了上一组、流水线填满)→ 新结果覆盖未接受组。
- **修复**:系数出口改 **2 深 FIFO**;发号闸改为"投影计数 < 2"(后经 I-19 补全)。
- **教训**:**1 深缓冲 + ready 可能当拍撤销 = 必丢数据;要么 2 深,要么 ready 恒定可预测。**

## I-15 系数 FIFO 指针越界(与 I-08 同型)

- **现象**:块内行 3/行 7 数据 X,`q_last` 永不到 huff,字节 0。
- **根因**:cf_wr/cf_rd 用 `[1:0]` +1 计数,走 0,1,**2,3**;数组只有 [0:1]。
- **修复**:`^ 2'd1` 翻转。
- **教训**:同 I-08。**这个 bug 类在本项目出现 3 次(I-08/I-15/huff wslot),写指针一律翻转。**

## I-16 decim 行缓冲读址冻结

- **现象**:色度流整行读同一 lbuf 条目(lbuf=207/197 恒定)。
- **根因**:rd_addr_r 只在偶行写时更新,奇行全程冻结在 pair-31。
- **修复**:偶列采样拍直接 `lbuf_dout <= lbuf[xcnt[...]]`(寄存读恰好落在
  奇列完成拍),删除 rd_addr_r 间接层。
- **教训**:BRAM 一拍延迟的"地址发射拍"必须与"使用拍"逐对核对,冻结地址 = 惨案。

## I-17 sof 像素两重错误

- **现象**:首行色度全错,lbuf 配对整体移一位(lbuf[1]=cb(3)+cb(4))。
- **根因**:sof 分支 (a) 清零 cb_sum 丢掉 (0,0) 的样本;(b) xcnt 清 0——但
  sof 像素本身就是列 0,下一个像素是列 1,xcnt 应置 1。
- **修复**:sof 存样本 + `xcnt <= 1`。
- **教训**:帧首特判要同时处理"数据"和"游标推进"两件事,漏一件就是移位。

## I-18 gather 窗口覆盖

- **现象**:64/96 块像素错(背压拉长发射时)。
- **根因**:`hold_input = pending_emit && emit_active && (epp==gpp)`,
  其中 epp==gpp 永假(发射期两指针必不同)→ 输入永不停,把正在等待发射的
  已完成窗口又写了一遍。tb_gather 理想时序下发射快于填充,侥幸全绿。
- **修复**:`hold_input = !cfg_seen || pending_emit`。
- **教训**:**永不成立的保护条件 = 没有保护;"单测时序理想化"是双刃剑——它验证不了背压路径。**

## I-19 发号闸漏算同拍 drain

- **现象**:cf_cnt 冲到 3(2 深数组装 3 项),第 3 推覆盖未读组;
  行 3 槽出现行 5 的输出。
- **根因**:闸 `cf_cnt < 2 || coef_pop` 只看了当拍 pop,漏了**同拍并发 drain
  的 push**(背靠背 P2 行 drain+issue 同拍)。
- **修复**:`cf_cnt_proj = cf_cnt + push - pop; gate = (proj < 2)`。
- **教训**:容量闸的判定对象是"下一拍落地前的占用",必须把同拍所有增减都投影进去。

## I-20 量化表索引缺组偏移

- **现象**:系数对、量化值错(±1~3);块 0 自然位 9 用了 Q=10 的条目算 Q=12。
- **根因**:每条 lane 查表 `qs(is_l, lane)`——每组都用表项 0-7,自然位
  {组号, lane} 的组偏移丢失。flat 又免疫(DC 外全零)。
- **修复**:组计数 gidx,索引 `{gidx, lane}`,coef_last 归零。
- **教训**:**8/cycle 流水线里"lane 内索引"必须显式拼上位组号;又一个 flat 免疫案例。**

## I-21 quant c1/c2 位宽

- **现象**:帧尾字节不出,探针显示 quant 出口 comp=2(golden 6)。
- **根因**:`reg [1:0] c1/c2` 截掉 comp[2](eof)——与 dct2d 的 core_comp 同型。
- **修复**:[2:0]。
- **教训**:侧带位([2]=eof)最容易在位宽缩窄时丢;位宽声明全项目统一排查过一遍。

## 探针方法论(本次调试沉淀)

1. **分层对拍**:每级出口(转换器原始流 / decim 流 / gather 块 / dct2d 系数 /
   quant 输出 / huff 字节)都有探针文件,对拍 golden 中间文件,一击定位层级。
2. **采样纪律**:探针一律 `always @(posedge)` 读**沿前值**(与消费端一致);
   negedge/沿后读在背靠背流上会读到下一组(本项目踩了 3 次)。
3. **小心探针自身 bug**:字节序取反、列/行布局混淆、空 tag 文件名、
   forever 挂死——探针读数前先证明探针是对的。
4. **警惕"常量图免疫"**:flat64 对 ±1 舍入、zigzag 混淆、组偏移、位宽截断
   全部免疫,四类 bug 都在 flat 全绿后由内容图暴露。**内容图必须进回归。**
5. **vopt 缓存**:`vsim` 可能复用旧 `_opt` 设计,vlog 后不重究化。
   可靠流程 = `vlog` + `vopt <lib>.<top> -o <新名> +acc` + `vsim <新名>`。
